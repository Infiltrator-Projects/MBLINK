# ELM327 Engine

MBLINK 0.2 establishes a portable C11 ELM327-compatible command engine above the platform-neutral transport ABI. It is intentionally independent of Bluetooth, CoreBluetooth, Swift and the Vgate product layer.

## Responsibilities

The ELM327 layer owns:

- bounded command validation and carriage-return framing;
- fragmented response accumulation;
- prompt detection at `>`;
- response normalisation and echo removal;
- `SEARCHING...` and `OK` metadata handling;
- adapter-status classification;
- deterministic adapter initialisation;
- one-command-at-a-time transport execution;
- timeout, cancellation and re-synchronisation state;
- adapter/protocol capability probing.

It does not own OBD-II PID decoding, ISO-TP, UDS, Mercedes-Benz interpretation or platform-specific BLE behaviour.

## Initialisation

The deterministic initialisation sequence is:

```text
ATZ
ATE0
ATL0
ATS0
ATH0
ATSP0
ATI
```

`ATSP0` is the initial automatic OBD protocol-selection policy. The final `ATI` response is retained as the adapter identity.

Configuration stages require a successful `OK` response. Reset and identity stages permit textual responses. Adapter errors move the state machine to an explicit failed state.

## Response model

Transport providers may deliver bytes in arbitrary fragments. The parser accepts partial input until the ELM prompt (`>`) is observed. It consumes exactly through the prompt and reports the number of bytes consumed so data following the prompt is never silently lost.

Normalisation removes command echo and line-ending noise while preserving payload lines. Recognised adapter results currently include:

- `NO DATA`;
- `STOPPED`;
- `UNABLE TO CONNECT`;
- bus initialisation errors;
- `CAN ERROR`;
- `BUFFER FULL`;
- unsupported-command `?`;
- generic adapter `ERROR`.

Empty prompt-only responses are classified as malformed.

## Session engine

`MblinkElm327Session` binds the parser to `MblinkTransport` and enforces one outstanding command at a time.

The caller supplies a monotonic millisecond clock and timeout for each command. Deadline arithmetic uses Infiltratr Common checked arithmetic and never wraps silently.

A completed command exposes its parsed `MblinkElm327Response`. Adapter-level results such as `NO DATA` still represent a completed transport transaction and remain available through the response object.

### Re-synchronisation rule

A timeout, cancellation or transport write failure can leave late bytes in flight. MBLINK therefore marks the session as requiring re-synchronisation and refuses to begin another command until the caller explicitly restores a known ELM command boundary or reconnects the transport.

This prevents a late response from one request being interpreted as the response to the next request.

### Callback rule

Session completion callbacks are synchronous and observational. The session blocks a new command from being started re-entrantly inside its own completion callback. Higher layers should defer the next command until the callback returns.

The session is deliberately single-threaded. A platform provider or application bridge must serialize access to one session instance.

## Capability probing

After initialisation, the probe state machine can request:

```text
AT@1
ATDP
ATDPN
```

`AT@1` is treated as optional because compatible adapters may not implement the descriptive command. `ATDP` and `ATDPN` capture the selected protocol description and numeric protocol identifier.

For `ATDPN`, MBLINK records whether the adapter reports automatic selection. The parser correctly distinguishes an automatic-prefix response such as `A6` from a single hexadecimal protocol identifier `A`.

The protocol probe may be repeated after vehicle communication has caused automatic protocol detection to settle.

## Test strategy

The ELM327 engine is tested without BLE hardware. Regression coverage includes:

- command framing and invalid input;
- fragmented input across arbitrary boundaries;
- prompt-boundary consumption;
- response classification;
- initialisation success and failure;
- deterministic mock transport execution;
- synchronous provider callbacks;
- re-entrant completion protection;
- one-command ownership;
- timeout and cancellation behaviour;
- deadline-overflow protection;
- transport-write failure;
- re-synchronisation enforcement;
- optional capability support;
- automatic/manual protocol-number parsing;
- malformed capability responses.

GitHub Actions builds and runs the portable suite on both Ubuntu and macOS under the project's strict C11 warning policy.

## Next layer

MBLINK 0.3 builds the standard OBD-II engine on top of this ELM327 foundation. PID discovery, live parameter decoding, DTCs, readiness and vehicle information remain separate from adapter command mechanics.
